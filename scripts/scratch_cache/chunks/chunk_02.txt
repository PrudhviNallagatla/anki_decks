Tracking Execution Statistics
 Track query execution statistics using pg_stat_statements extension
 pg_stat_statements tracks statistics across all databases of a cluster
 pg_stat_statements extension add view, functions and configuration parameters
 View - pg_stat_statements to access the query statistics
 Functions - pg_stat_statements_reset to reset the statistics
© E DB 2 0 2 5 — A LL R I G HT S R E SE R V E D.

pg_stat_statements Setup
 Add pg_stat_statements to shared_preload_libraries parameter in
postgresql.conf
 Configurable parameters:
 pg_stat_statements.max -Maximum number of tracked statements, default 5000
 pg_stat_statements.track – Which statements are counted, top, all or none. Default is top
 pg_stat_statements.track_utility - Track commands other than SELECT, INSERT, UPDATE and
DELETE. Default is ON
 pg_stat_statements.track_planning – Track planning operations and duration
 pg_stat_statements.save - Whether save statement statistics across server shutdowns. Default is ON
 Restart the Database Cluster
 Connect with a database and enable pg_stat_statements extension

Installation - Prerequisites
 PEM server requires a backend database for storing monitoring data.
 Backend database can be Enterprise Postgres or PostgreSQL. Recommended
version is 12 or higher.
 It is recommended to install PEM server on a system with at least 4 CPU cores,
8GB of RAM and 100GB of Storage.
 Additional disk space is required based on number of monitored instances and
retention period for monitoring data.
 pg_hba.conf entries are required for PEM server PEM agent and PEM-HTTPD
service connection to managed or unmanaged instances.
